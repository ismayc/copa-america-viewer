# Architecture

A contributor's map of the Copa América 2024 Schedule Viewer. The README covers
*what the app does*; this covers *how the code is laid out* and how data flows
through it. Day-to-day "what changed when" lives in [`NEWS.md`](./NEWS.md); the
authoritative per-function detail lives in each module's header comment — this
file is the index that points you at the right one.

The app is a client-only React 18 + Vite SPA. There is no backend: all logic
runs in the browser (plus a handful of Node scripts for CI/data regeneration and
one Netlify function for the calendar feed).

## The format, and why it shapes the code

Sixteen teams, four groups of four, **top two advance** — and no best-third
route. That one fact removes a whole layer the sibling viewers need: with no
cross-group third-place race, every qualification question is answerable inside a
single group. Clinch, elimination and opponent-lock detection are all per-group
here; the Euro and World Cup viewers each carry a combinations table and a
cross-group bounding pass that simply have no counterpart in this repo.

Copa also keeps a **third-place play-off** (the European Championship dropped
its after 1980). It hangs off the bracket rather than sitting in it, and it is
the one place the "Loser Match N" feed form is exercised.

## Data flow at a glance

```
static schedule (src/data)              live feeds (src/services)
  matches · teams · venues                 OpenFootball (record) ─┐
        │                                  ESPN (live overlay)   ─┤ merge
        └──────────────┬─────────────────────────────────────────┘
                       ▼
        merged matches  (App.jsx state, refreshed on a timer)
                       │
   ┌───────────────────┼──────────────────────────────────────────┐
   ▼                   ▼                   ▼                       ▼
 qualification       clinch /           asItStands            bracketResolve
 (standings,         eliminationCheck   (provisional QF       (fill bracket
  tie-breakers)      (guaranteed        projection)            placeholders as
                      outcomes)                                teams resolve)
                       │
                       ▼
                   components/  (Standings, Bracket, WeekView, …) render it
```

Everything downstream of the merge is **pure**: given a `matches` array it
recomputes standings, clinches, projections and bracket fills with no side
effects — which is why most logic is unit-testable without the DOM.

## `src/data` — static inputs

| File | Exports | Role |
| --- | --- | --- |
| `matches.js` | `MATCHES`, `STAGE_LABELS`, `STAGE_ORDER` | The frozen 32-match schedule (kickoffs, venues, group/knockout slot labels). Source of truth for structure; regenerated by `fetch:tournament`, asserted against `test/fixtures/official-kickoffs.js`. |
| `teams.js` | `TEAMS`, `FLAG_BY_TEAM`, `ALL_TEAMS` | 16 teams by group, flag/name lookups. `FLAG_BY_TEAM[name]` doubles as the "is this a real team?" test in the UI. |
| `venues.js` | `VENUES` | 14 host stadiums (name, city, country, region), keyed by stadium — two of them are in Kansas City. |
| `broadcast.js`, `teamTimezones.js`, `groupColors.js` | — | US TV/streaming, per-country kickoff times, group accent colors. |

There is no ranking table and no combinations table. CONMEBOL's last tie-breaker
is a drawing of lots, not a ranking, so it is stood in for by a stable
alphabetical order (`byLots` in `qualification.js`) rather than by data.

## `src/services` — live data ingestion & merge

Two feeds, merged in priority order; the merge is where cryptic feed spellings
are normalised to our canonical names.

- **`results.js`** — OpenFootball `copa.txt`, the **source of record** for final
  scores and for resolving knockout team names. Unlike the sibling competitions
  this one is published as **plain text**, so this module carries a runtime parser
  (`parseCupTxt`) rather than reading JSON. Key exports: `fetchResults`,
  `applyResults`, `normalizeTeam`, `pairKey`, `isRealTeam`, `matchKey`,
  `openFootballFinalScore`.
- **`espn.js`** — ESPN public scoreboard, the **live in-match overlay** (clock,
  provisional score, goal/card events). `fetchLive`, `applyLive`, `espnFinalScore`,
  `normEspn`. Used only while a match is live or just-finished before OpenFootball
  posts; OpenFootball wins once it has the score.
- **`espnStats.js`, `espnMatchStats.js`** — Golden Boot enrichment and per-match
  player lines for the stats view and player pop-outs.
- **`reconcile.js`** — reconciles the feeds per match → "confirmed by N sources" /
  "sources disagree". Source-agnostic: it took the drop from three feeds to two
  without a code change.
- **`goalNotify.js`** — opt-in browser goal notifications for followed teams.

`App.jsx` owns the fetch loop: it polls every ~2 min, dropping to ~30 s while any
match is live, and recomputes the derived state below on each refresh.

## `src/utils` — derived logic (pure)

**Standings & qualification**
- `qualification.js` — `computeQualification` (all four tables), `rankGroup`,
  `headToHead`, `groupComplete`, `rowStatus`, `ADVANCING_PER_GROUP`. Implements
  CONMEBOL's tie-breaker order: points → **overall goal difference → goals scored
  → head-to-head** → fewest reds → fewest yellows → drawing of lots. The
  GD-before-head-to-head inversion versus UEFA is the thing to preserve.
- `tiebreakNotes.js` — `softTiebreaks`, `TIEBREAK_LABEL`: detect placings
  separated only by cards or by the drawing of lots (the "⚖️" cases).
- `standings.js` — small presentation helpers for the tables.

**Guaranteed outcomes**
- `clinch.js` — `computeClinch` plus `resolveClinchedSlots` / `resolveRunnerUpSlots`
  (fill group-winner/runner-up bracket slots), `newlyClinched`, `clinchHeadline`,
  `clinchBadge`. Marks teams 🥇/🥈/✅/❌ once mathematically settled. Statuses are
  `won-group | runner-up | top2 | eliminated` — there is no `third`.
- `eliminationCheck.js` — exact per-group scoreline enumeration for
  elimination/advancement: `eliminationStatus`, `survivingTeams`, `isAlive`. Stays
  silent rather than guessing when a group is too open to enumerate.
- `opponentClinch.js` — `lockedOpponent`: has a team's quarter-final opponent
  stopped being able to change? A two-group question here, and nothing more.

**Projection & bracket**
- `asItStands.js` — `projectKnockout`: the provisional "as it stands" quarter-final
  projection. Returns `perGroup[g] = { first, second }` and nothing else.
- `bracketResolve.js` — `resolveBracket` (full pipeline), `resolveKnockoutSlots`
  (propagate "Winner/Loser Match N" up the rounds), `decideMatch` (winner/loser of
  a finished tie; null while live or drawn without pens). Conservative: a slot
  stays a placeholder until genuinely settled.
- `bracket.js` — `BRACKET` (two-sided layout plus a `third` key for the play-off),
  `matchesByNum`, `groupSlotMap`, `feederTeams`, `pathToFinal`, `knockoutTeams`.
- `slots.js` — the slot-label grammar (`ENTRY_ROUND = 'QF'`, `WINNER_GROUP`,
  `RUNNERUP_GROUP`, `WINNER_MATCH`, `LOSER_MATCH`, `entryMatches`, `slotLabels`).
- `outlookEnum.js` — the (group-stage-only) QF Outlook: goal-difference margin
  enumeration with weighted per-group dedup. Runs in a web worker.

**Group-stage tools & misc**
- `scenarios.js` — deterministic what-if picks; `groupStageArchived` / `stageArchived`
  (retire the group-stage-only tabs once every group game is final).
- `tournamentStats.js` — Golden Boot table, tournament totals, `activeTeams`,
  `teamRecord` (the knockout "tale of the tape").
- `time.js` — `formatTime`, `dayKey`, `matchStatus`, `liveState`,
  `teamLocalKickoffs`, `teamKickoffTooltip`.
- `week.js`, `search.js`, `urlState.js`, `ics.js` — week-calendar bucketing,
  filtering, shareable-URL (de)serialization, `.ics` generation.

## `src/components` & `src/context`

`App.jsx` is the shell: data loop, filters, timezone, spoiler mode, view routing,
and the group-stage-archived gating. Views: `Standings`, `Bracket`,
`RadialBracket`, `WeekView`, `StatsView`, plus the group-stage `ScenariosView` /
`OutlookView`. Cards/modals: `MatchCard`, `MatchDetail`, `DayMatchesModal`,
`GroupGamesModal`, `CalendarModal`, `PlayerDetail`, `Filters`, `NextMatch`,
`ChampionBanner`, `LiveBadge`, `ScoreCheck`. Cross-cutting state lives in
`context/` (`follow.jsx` for starred teams, `path.jsx` for the traced route to
the Final, `detail.js` for the match-detail modal).

The bracket's **potential-matchup** display (a "Winner Match N" slot expanding to
the candidate pair, cascading round by round) lives in `bracket.js`'s
`feederTeams` helper — round-agnostic and per-slot by construction, which is why
the third-place play-off's "Loser Match N" slots expand with no special case.

## `scripts` — data regeneration & CI

Run with `node scripts/<name>.mjs`; the npm aliases are in `package.json`. These
must use **only Node built-ins and in-repo source** (no npm deps) — enforced by
`test/scripts-runtime.test.js`.

- **`fetch-tournament.mjs`** (`npm run fetch:tournament`) — rebuild
  `src/data/{matches,teams,venues}.js` from ESPN (structure, ids, kickoffs,
  scores) + OpenFootball (goal scorers). Fails if the two disagree on a score.
- **`make-official-fixture.mjs`** (`npm run fixture:official`) — rebuild
  `test/fixtures/official-kickoffs.js` from OpenFootball *only*, deliberately a
  different source, so `data.test.js` comparing the two is a real cross-check.
- **`check-bracket-consistency.mjs`** (`npm run check:bracket`) — our bracket
  layout versus the official draw.
- **`coverage-badge.mjs`** — turn the coverage summary into the shields endpoint.

Both generators correct the same upstream defect: `copa.txt` transposes the
kickoff time and venue of the two 6 July quarter-finals. That fix lives in three
places (both generators and the Netlify calendar function) and must not be
"fixed" by editing the data instead.

## Outside `src`

- `netlify/functions/calendar.js` — the auto-updating `webcal://` `.ics` feed
  (fetches the live schedule per request; mirrors `utils/ics.js` formatting). It
  is **ESM on purpose**: the package is `"type": "module"`, so a CommonJS function
  502s on the Netlify Git-build path.
- `test/` — Vitest suite (units + jsdom component tests). Fixtures in
  `test/fixtures/` freeze real upstream data (`official-kickoffs.js`,
  `final-group-results.js`, `group-stage-md3.js`, `copa-txt-snapshot.txt`, …) as
  regression anchors.

## Conventions

- **Purity downstream of the merge.** Logic takes a `matches` array and returns
  derived data; no module mutates its input. Tests pass synthetic `matches`.
- **Conservative resolution.** Clinch/bracket code only commits an outcome when
  mathematically guaranteed; provisional views (projection, outlook) are where
  "what could happen" lives.
- **Canonical names.** Every feed normalises to the `src/data/teams.js` spelling
  at ingestion. Both alias maps are currently **empty**, and
  `test/team-resolution.test.js` refuses any alias key that never appears in the
  captured feed — an inherited alias (`'United States' → 'USA'`) once rewrote a
  canonical name to a non-team and silently dropped every USA match.
- **This edition is finished.** `src/data/matches.js` ships with every result, so
  tests wanting a pre-tournament board ask for one explicitly via
  `test/helpers/tournament.js`'s `unscored()`. App-level tests of the live layer
  must mock the module to a blank board, or the live overlay always defers to the
  recorded score and the whole subsystem is unreachable.
- **Module header comments are the spec.** Before changing a util, read its top
  comment — it states the invariant the rest of the code (and tests) rely on.
